# DT20: локальная разметка в браузере

Инструмент A для независимых человеческих эталонов. Он использует канонические
snapshots и формат `evals.prepare`; обращения к моделям и внешним сайтам отсутствуют.
Запуск не является разрешением на live-оценку и не создаёт официальный `results.json`.

## Запуск Windows

Из корня существующего репозитория с установленными зависимостями:

```powershell
$env:PYTHONPATH = 'backend'
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m evals.review --inputs data/private/a02-inputs.v1.json --workspace data/private/a02-review --port 8787
```

Откройте `http://127.0.0.1:8787`. Сервер слушает только этот компьютер. Работает
один процесс на рабочую папку. Повторный запуск открывает сохранённое состояние.
Для Linux/macOS используйте `.venv/bin/python` и обычное присваивание `PYTHONPATH=backend`.
Новые зависимости не требуются. Чтобы остановить обычный запуск, нажмите Ctrl+C.

## Работа человека

1. Открывайте диалоги слева и читайте реплики. Фильтры: язык, канал и исходный ID.
   Звонки представлены текстовыми транскриптами; этот инструмент не скачивает аудио.
2. Выберите около 20–25 примеров. В поле «Группа сценария» объедините переводы,
   перефразирования и версии одного разговора. Не назначайте уникальную группу
   каждому диалогу автоматически. Введите имя человека, проверившего группировку.
3. Сохраните выбор. Задайте число групп для отложенной проверки и seed, нажмите
   «Посмотреть разделение». Проверьте количество диалогов, языки и каналы в обеих
   частях. До просмотра предсказаний можно корректировать состав и группы.
4. Нажмите «Зафиксировать выборку». С этого момента состав, seed и группы этой
   рабочей папки неизменны. Появятся пустые ответы. Это ещё не эталоны качества.
5. Для каждого критерия выберите ответ по сохранённой рубрике, напишите обоснование
   и выберите начало/конец подтверждающего участка. При необходимости добавьте
   несколько диапазонов. Выбранные реплики подсвечиваются; учитываются все роли.
6. «Сохранить черновик» разрешает продолжить позже. «Завершить разметку» требует
   всех ответов, пояснений и evidence, имени и подтверждения понимания языка.
   Неприменимость требует причины. Недопустимые ступени и чужие реплики отклоняются.
   Пока сохранение и загрузка сохранённой версии не завершены, поля и кнопки
   заблокированы. При ошибке сохранения введённые данные остаются для исправления и повтора.
7. Спорный случай требует описания неоднозначности, решения и подтверждения вторым
   человеком с другим именем. Флажок означает личное подтверждение; система не
   проверяет личность человека и не заменяет смысловую проверку. Редактирование
   завершённого ответа через сохранение черновика снимает отметку завершения.
8. Экспортируйте настройку и проверку отдельно. Часть экспортируется только после
   завершения всех входящих в неё диалогов. Holdout не используйте для настройки.

Не копируйте ответы оцениваемой модели в человеческие эталоны. Памятка по восьми
исходным критериям и спорным случаям — [ANNOTATION_GUIDE](ANNOTATION_GUIDE.md).
Если исходные файлы изменились, приложение потребует другую рабочую папку.
Не меняйте зафиксированную выборку после просмотра результатов ради улучшения метрик.

## Что сохраняется

В `--workspace` создаются последовательные неизменяемые `revision-00000000.json`
и следующие ревизии. Они содержат выбор, hash входов и после фиксации полный
канонический `DraftDocument`. Сначала записывается временный файл, затем новая
ревизия публикуется переименованием. Неудачная запись не изменяет состояние в памяти.
Старый запрос из другой вкладки получает конфликт вместо перезаписи новых данных.

Экспорт создаёт новую папку `exports/r<ревизия>-<часть>-<суффикс>`:

- `references.json` — массив ReferenceRecord для `evals.compare`, итог считает scorer;
- `inputs.json` — входы только выбранной части для будущего разрешённого прогона;
- `annotations.json` — полные ответы, snapshots и сведения о проверяющих этой части.

В экспорте tune нет содержимого holdout. Общий канонический draft с историей
остаётся в соответствующей ревизии рабочей папки. Сохраните её вместе с результатами.
Повторный экспорт создаёт новую папку; существующие файлы не перезаписываются.
Ревизии и экспорты приватны и не должны публиковаться в Git.

## Границы и проверки

Host/Origin и токен страницы ограничивают запись локальным приложением, размер
запроса ограничен. Тексты выводятся через textContent; CSP запрещает встраивание
и внешние ресурсы. Нет внешних шрифтов, аналитики, audio URL в ответах и API-ключей.
Это локальный инструмент, без системы аккаунтов для публикации в интернет.

Проверки: `backend/tests/evaluation/test_review_workspace.py` — выборка, разделение,
история, конфликт вкладок, сбой записи, расширенная рубрика, evidence, ручная проверка,
экспорт, приватные пути и HTTP-границы. В браузере Edge на синтетике проверены
выбор/перезагрузка, предпросмотр, фиксация, пустые ответы, доказательства, частичное
сохранение, три завершённых диалога, экспорт, отсутствие XSS и внешних запросов,
а также отсутствие горизонтального переполнения при ширине 375 px.
Эти проверки не являются человеческой разметкой настоящего DEV или оценкой accuracy.

Регрессия потери evidence при сохранении: `node --test evals/tests/review_ui.test.cjs`.
Она запускает настоящий JS формы в JSDOM с задержанными синтетическими ответами,
проверяет блокировку добавления/удаления диапазона, последующее редактирование,
повторное сохранение и сохранность ввода при ошибке. Нужны Node и зависимости
из `npm --prefix frontend ci`; новых зависимостей нет. Pytest включает эту проверку
через `backend/tests/evaluation/test_review_ui.py`. Если Node/JSDOM не установлены,
она явно пропускается; в полном CI они устанавливаются перед pytest.
