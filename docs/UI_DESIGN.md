# Минимальный интерфейс этапа 0

Владелец: B. Интерфейс показывает результат одного синтетического примера, чтобы
команда проверила контракт, отображение N/A и переход к доказательству до живой модели.

## Визуальное решение

Светлая рабочая панель с глубоким зелёным акцентом, спокойной навигацией и двумя
основными колонками: исходный разговор и оценка. Текст разговора остаётся рядом
с объяснением, а выбранное доказательство выделяется и получает клавиатурный фокус.
Итог и вклад секций расположены одной полосой над ними. На узком экране колонки
складываются последовательно; мобильный transcript ограничен по высоте.

Палитра: фон `#F3F6F5`, поверхность `#FFFFFF`, текст `#20332C`, вторичный текст
`#617269`, акцент `#145A46`, предупреждение `#FCF7E9`. Семантические токены находятся
в `frontend/src/tokens.css`. Шрифт — системный Segoe UI с Arial/sans-serif fallback,
без сетевой загрузки. Цвет дополняется текстовыми статусами, видимый focus сохранён.

В поиске UI/UX найдена подходящая категория Data-Dense Dashboard; предложенный там
маркетинговый Enterprise Gateway не применялся. Выбор структуры основан на задаче
проверяющего: сопоставить ответ критерия и исходное сообщение. Внешние UI-библиотеки,
анимационные пакеты, удалённые изображения и шрифты не требуются.

## Границы

- Загрузка — только `GET /api/v1/demo`, с явным mock-баннером.
- Frontend форматирует Decimal-строки из API; не вычисляет баллы или секционные итоги.
- Ошибка HTTP, пустой ответ и незавершённая оценка имеют отдельные состояния.
- Нет автоматического fallback на fixture: серверная ошибка остаётся ошибкой.
- Evidence берёт текст из `conversation.messages`, а не из ответа модели.
- Ссылка на аудио показывается только при наличии `audio_url`; seek не выдумывается.
- Импорт, реальная оценка, редактор и апелляции остаются следующими задачами B/C.

## Проверки

Из `frontend`: `npm ci`, `npm run generate:api:check`, `npm run check`.
Vitest проверяет evidence/focus, отсутствие подмены при HTTP 503 и повтор запроса,
пустое состояние, отсутствие итога незавершённой оценки.

Перед `npm run test:e2e` запустите backend на `127.0.0.1:8000` по README.
Playwright самостоятельно запускает Vite на `127.0.0.1:5173` (или использует уже
запущенный вне CI). Первый сценарий использует настоящий `/api/v1/demo`; остальные
проверяют ошибку и узкую раскладку с reduced motion и клавиатурным переходом.
Если Playwright Chromium не установлен, выполните `npx playwright install chromium`.
Для локальной проверки с уже установленным Edge в PowerShell можно задать
`$env:CQA_BROWSER_CHANNEL='msedge'`; в CI используется установленный Chromium.

OpenAPI генерируется backend-скриптом. `npm run generate:api` создаёт
`src/api/generated/schema.d.ts`; файл не редактируется вручную.
