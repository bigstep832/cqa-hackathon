# Groq: подключение и первая проба

На 08.11.2026 подключён `provider="groq"` через общий `EvaluationProvider`.
Рубрика, parsing, проверка evidence и scorer остаются общими с другими моделями.
API/jobs и экспорт распознают Groq как `external_api`, без подмены именем OpenAI/local.
Проверка публикации и экспорт также распознают ключи Groq как секреты.

## Транспорт

- Endpoint фиксирован: `https://api.groq.com/openai/v1/chat/completions`.
- Модель первой пробы: `openai/gpt-oss-120b`.
- Формат: `response_format=json_schema`, `strict=true`; все текущие критерии.
- Для GPT-OSS 120B/20B: `reasoning_effort=medium`, `include_reasoning=false`.
  Краткое объяснение и evidence остаются обязательными полями ответа.
- Ограничение `max_completion_tokens` включает reasoning. `completion_tokens`
  учитываются один раз. Реальный денежный расход в метаданных остаётся `null`,
  поскольку API не возвращает подтверждённый биллинг.
- Нет автоматической смены модели, перехода в mock или следования redirects.
  Ограничения числа запросов, попыток, области данных и бюджета проверяет LivePlan.

Создание адаптера само по себе не выполняет HTTP:

```python
from app.evaluation.factory import ProviderConfig, create_provider

provider = create_provider(ProviderConfig(
    provider="groq", api_key=key_read_locally,
    max_attempts=1, max_output_tokens=4096,
))
```

В `EvaluationSettings` и согласованном `LivePlan` нужны одинаковые
`provider="groq"`, точный `model` и `mode="live"` в settings.
Включение backend по-прежнему требует `LIVE_EVAL_ENABLED=true`, `CQA_LIVE_PLAN`
и приватного `MODEL_API_KEY`. `local_base_url` для Groq запрещён.
Схемы API и UI изменять не требуется. Синтетическая проба не включает live в приложении.

Сначала запускать обычный `evals.live` без `--execute`: он проверяет план без сети.
Реальный запуск требует согласованного набора, лимитов и явного `--execute`.
Порядок и поля плана описаны в [A01_OFFLINE_HANDOFF](A01_OFFLINE_HANDOFF.md).

## Бесплатная синтетическая проба 08.11.2026

В консоли проверен текущий тариф Free ($0), без подключения карты/платного тарифа.
Выполнен один запрос, без retries, DEV, контроля и аудио; бюджет плана — $0.
Нулевые цены применимы только к проверенному Free-аккаунту и текущему разрешению.
Они не являются универсальным тарифом Groq. После изменения биллинга или истечения
даты проверки нужен новый план. Лимиты Free проверяются в консоли конкретного аккаунта.

Вход — существующий публичный `fixtures/synthetic/conversation.json`, инструкция
`cqa-rubric-v1`, pipeline `groq-chat-v1`. Эталонные ответы модели не передавались.
Результат: HTTP 200, 8 ответов с объяснениями и технически валидными ссылками,
6,13 с, 3973 входных и 1538 выходных токенов. Исходный результат сохранён без правок.

| Критерий | Разметка примера | Groq |
| --- | --- | --- |
| C01 | Да | Да |
| C02 | N/A | Нет |
| C03 | N/A | N/A |
| C04 | 15 | 15 |
| C05 | Да | Да |
| C06 | 7 | 10 |
| C07 | Да | Да |
| C08 | Нет | Нет |
| Итог | 85,38 | 75,00 |

Совпали 6/8 значений (причины N/A не сравниваются как текст).
C02 смешан с полнотой ответа: клиент уже сформулировал запрос; неотвеченная часть
относится к C04. C06 не снизился за исправленную неточность в инструкции.
Evidence C04 ссылается только на m3–m5, поэтому не показывает исходный дополнительный
вопрос из m1: техническая валидность ссылок не заменяет смысловую проверку.

Это известный пример разработки, **не независимый holdout и не Ground Truth жюри**.
Процент общей точности и преимущество модели по одному примеру не устанавливаются.
Следующий этап — заранее выделенная независимая разметка RU/KZ/EN, проверка N/A,
C04/C06/C08 и смысла evidence.

## Разрешённый диагностический прогон A-02

8 ноября пользователь подтвердил ответы 25 выбранных диалогов и отдельно разрешил
передать Groq их тексты: 20 чатов и транскрипты 5 звонков, максимум 25 запросов,
по одной попытке, бюджет $0, только Free. Это разрешение не распространяется
автоматически на остальные 40 DEV, контроль или аудиофайлы.

До DEV проверены ещё два варианта инструкции на том же синтетическом примере:
v2 и v3 дали по 5/8 совпадений против 6/8 у исходной v1. Этот единственный пример
не устанавливает превосходство модели или промпта; улучшение не подтверждено.
Изменения не приняты: для всего DEV-прогона закреплены `cqa-rubric-v1` и
`groq-chat-v1`. Три синтетические пробы суммарно использовали 16 514 токенов.

Запуск использует копию SQLite, неизменные snapshots и стандартные jobs/dispatches
backend. Отдельный приватный manifest ограничивает отправку ровно разрешёнными
версиями; журнал сохраняет попытку до передачи. Повторов, смены модели и подключения
платного тарифа нет. HTTP 429 останавливает весь пакет. Пояснения и исходные оценки
сохраняются без ручной подстановки подтверждённых ответов.

Происхождение эталонов — `team_human_confirmed_ai_draft`: AI-черновик проверен одним
человеком. Это не независимая двойная разметка и не Ground Truth организаторов.
Предложенное разбиение 16/9 заморожено до предсказаний Groq, но не является слепым
holdout для Codex, ранее видевшего черновик. Отчёт должен сохранять это ограничение.

Фактический результат: 20 чатов оценены, первый звонок отклонён HTTP 413,
четыре остальных не отправлены. Метрики, ошибки применения рубрики, ограничения
Free и сохранённые данные — [A02_GROQ_DIAGNOSTIC](A02_GROQ_DIAGNOSTIC.md).

## Компактное представление запроса (кандидат, офлайн)

`ProviderConfig(request_encoding="compact-v1")` включает отдельный формат для
OpenAI/Groq. По умолчанию остаётся `canonical`; Gemini и local этот формат отклоняют.
Профиль инструкции выбирается независимо через `instruction_profile`.

Компактный формат заменяет повторяющиеся ключи таблицами с именованными колонками,
выносит общий префикс/суффикс исходных timestamps и повторяющиеся части JSON Schema
в `$defs`/`$ref`, поддержанные [Structured Outputs Groq](https://console.groq.com/docs/structured-outputs).
Сохраняются полный текст каждой реплики, все роли, точные ID, порядок и исходные
метки времени; даты не округляются и не перепарсиваются. Полная динамическая рубрика,
включая описания ступеней, N/A, веса и дополнительные критерии, восстанавливается
обратным преобразованием. Ответ модели имеет прежнюю структуру и проходит прежний parser.
В metadata pipeline получает суффикс `+cqa-compact-v1`; это изменение запроса,
поэтому результаты нельзя выдавать за запуск прежнего pipeline.

Проверены точное восстановление всех 25 выбранных локальных snapshots и синтетические
случаи RU/KZ/Unicode/непоследовательных ID/null timestamps/добавленных критериев.
После раскрытия `$ref` все ограничения ответа совпадают с исходной схемой.
Это доказывает сохранение данных в представлении, **не одинаковое понимание моделью**
и не повышение точности. Живой прогон этого формата ещё не выполнен.

Оценки tokenizer `o200k_harmony` для `cqa-rubric-v4-candidate` ниже включают резерв
384 токена на служебное представление и лимит ответа. Серверное число токенов может
отличаться. У ранее полученных 20 ответов фактический output был 1178–1995 токенов;
для более длинного звонка лимит 2048 не гарантирует завершение.

| Звонок | Input + резерв + output 2048 | С output 3072 |
| --- | ---: | ---: |
| D61 | 7288 | 8312 |
| D62 | 7321 | 8345 |
| D63 | 6785 | 7809 |
| D64 | 7392 | 8416 |
| D65 | 8234 | 9258 |

При наблюдавшемся лимите Free 8000 TPM D65 остаётся блокером; его текст не сокращается.
D63 уже использовал разрешённую попытку и не отправляется повторно автоматически.
Для D61/D62/D64 один компактный запрос с output2048 помещается в оценку, но это ещё
не разрешает повторные запросы, не доказывает достаточную длину ответа и не отменяет
общий дневной лимит/остановку по 429. Исходный baseline и его журнал не перезаписываются.
