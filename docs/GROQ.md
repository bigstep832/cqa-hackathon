# Groq: подключение и первая проба

На 08.11.2026 подключён `provider="groq"` через общий `EvaluationProvider`.
Рубрика, parsing, проверка evidence и scorer остаются общими с другими моделями.
API/jobs и экспорт распознают Groq как `external_api`, без подмены именем OpenAI/local.
Проверка публикации и экспорт также распознают ключи Groq как секреты.

## Транспорт

- Endpoint фиксирован: `https://api.groq.com/openai/v1/chat/completions`.
- Модель первой пробы: `openai/gpt-oss-120b`.
- Формат: `response_format=json_schema`, `strict=true`; все текущие критерии.
- Для GPT-OSS 120B/20B: `reasoning_effort=medium`, `include_reasoning=false`.
  Краткое объяснение и evidence остаются обязательными полями ответа.
- Ограничение `max_completion_tokens` включает reasoning. `completion_tokens`
  учитываются один раз. Реальный денежный расход в метаданных остаётся `null`,
  поскольку API не возвращает подтверждённый биллинг.
- Нет автоматической смены модели, перехода в mock или следования redirects.
  Ограничения числа запросов, попыток, области данных и бюджета проверяет LivePlan.

Создание адаптера само по себе не выполняет HTTP:

```python
from app.evaluation.factory import ProviderConfig, create_provider

provider = create_provider(ProviderConfig(
    provider="groq", api_key=key_read_locally,
    max_attempts=1, max_output_tokens=4096,
))
```

В `EvaluationSettings` и согласованном `LivePlan` нужны одинаковые
`provider="groq"`, точный `model` и `mode="live"` в settings.
Включение backend по-прежнему требует `LIVE_EVAL_ENABLED=true`, `CQA_LIVE_PLAN`
и приватного `MODEL_API_KEY`. `local_base_url` для Groq запрещён.
Схемы API и UI изменять не требуется. Синтетическая проба не включает live в приложении.

Сначала запускать обычный `evals.live` без `--execute`: он проверяет план без сети.
Реальный запуск требует согласованного набора, лимитов и явного `--execute`.
Порядок и поля плана описаны в [A01_OFFLINE_HANDOFF](A01_OFFLINE_HANDOFF.md).

## Бесплатная синтетическая проба 08.11.2026

В консоли проверен текущий тариф Free ($0), без подключения карты/платного тарифа.
Выполнен один запрос, без retries, DEV, контроля и аудио; бюджет плана — $0.
Нулевые цены применимы только к проверенному Free-аккаунту и текущему разрешению.
Они не являются универсальным тарифом Groq. После изменения биллинга или истечения
даты проверки нужен новый план. Лимиты Free проверяются в консоли конкретного аккаунта.

Вход — существующий публичный `fixtures/synthetic/conversation.json`, инструкция
`cqa-rubric-v1`, pipeline `groq-chat-v1`. Эталонные ответы модели не передавались.
Результат: HTTP 200, 8 ответов с объяснениями и технически валидными ссылками,
6,13 с, 3973 входных и 1538 выходных токенов. Исходный результат сохранён без правок.

| Критерий | Разметка примера | Groq |
| --- | --- | --- |
| C01 | Да | Да |
| C02 | N/A | Нет |
| C03 | N/A | N/A |
| C04 | 15 | 15 |
| C05 | Да | Да |
| C06 | 7 | 10 |
| C07 | Да | Да |
| C08 | Нет | Нет |
| Итог | 85,38 | 75,00 |

Совпали 6/8 значений (причины N/A не сравниваются как текст).
C02 смешан с полнотой ответа: клиент уже сформулировал запрос; неотвеченная часть
относится к C04. C06 не снизился за исправленную неточность в инструкции.
Evidence C04 ссылается только на m3–m5, поэтому не показывает исходный дополнительный
вопрос из m1: техническая валидность ссылок не заменяет смысловую проверку.

Это известный пример разработки, **не независимый holdout и не Ground Truth жюри**.
Процент общей точности и преимущество модели по одному примеру не устанавливаются.
Следующий этап — заранее выделенная независимая разметка RU/KZ/EN, проверка N/A,
C04/C06/C08 и смысла evidence. Отправка DEV/контроля Groq пока не разрешена.
