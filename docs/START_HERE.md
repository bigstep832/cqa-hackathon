# Старт команды и ранняя передача задач

Этот документ позволяет B и C начать независимо от готовности настоящей модели.
Этап 0 даёт общий контракт, синтетический результат и запускаемый каркас.
В этой ветке backend выполняет импорт, задания, решения по апелляциям и экспорт.
Состояние совместной приёмки приведено в [ACCEPTANCE](ACCEPTANCE.md).

## Прочитайте перед изменениями

1. Корневой [AGENTS.md](../AGENTS.md), даже если ИИ не загрузил его автоматически.
2. [README](../README.md): установка и запуск.
3. [PROJECT_BRIEF](PROJECT_BRIEF.md), [API_CONTRACT](API_CONTRACT.md).
4. Свою роль в [TEAM_PLAN](TEAM_PLAN.md), первый task в [TASKS](TASKS.md)
   и соответствующий файл из `prompts/`.

Канонические машинные источники: `backend/app/contracts/`,
`config/checklists/default.v1.json`. OpenAPI и TS-типы генерируются.
Не копируйте схемы в собственные независимые интерфейсы.

инфраструктуру/тестирование B/C. B может работать на fixture, C — на валидном JSON,
не ожидая API-ключей или DEV.

## Рабочий цикл

- Начните от текущего интеграционного `main`, проверьте `git status`.
- Создайте короткую ролевую ветку `feat/a-*`, `feat/b-*` или `feat/c-*`.
- Для параллельных агентов используйте отдельные clones/worktrees.
- Перед правками подтвердите границы задачи и наличие чужих незакоммиченных изменений.
- Изменение DTO: предложить A → согласовать → обновить Pydantic →
  экспортировать OpenAPI → сгенерировать TS → уведомить B/C.
- Проверки выполняет владелец изменённого модуля. Перед handoff сообщите команды,
  результат, остатки и следующий task. При подключённом GitHub используйте PR;
  репозиторий команды — `bigstep832/cqa-hackathon`.

## Первый запуск

Выполните команды README. Откройте `/health`, затем frontend и synthetic demo.
Баннер mock обязателен. Кнопки будущих действий не должны изображать успешный импорт
или апелляцию. Используйте серверные ответы и состояние задания из [API_CONTRACT](API_CONTRACT.md).

До разрешения платных вызовов A продолжает локальную разметку A-02 и ревью A-04.
C не должен ждать доступности временного API: ручной импорт — независимый первый шаг.
Фактические live-вызовы пока имеют открытые условия из DECISIONS.
