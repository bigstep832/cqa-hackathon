# Экспорт результатов хакатона

Команды запускаются из корня репозитория в окружении проекта. Они читают SQLite локального backend. CLI загружает корневой `.env`, а уже выставленные переменные среды имеют приоритет. Во время экспорта и проверки сеть не требуется.

## Репетиция до выдачи контроля

```sh
python scripts/submission.py rehearse
python -m pytest backend/tests/workflow/test_submission.py backend/tests/workflow/test_submission_storage.py
```

Первая команда проходит весь путь от синтетического mock до проверенного JSON в игнорируемом `work/rehearsal/results.json`. В наборе девять успешных примеров и одна ошибка. Вектор из приложения организаторов даёт 85.38. Этот файл содержит учебные ID и модель-заглушку. Официальные пути доступны только командам с данными реального backend.

## Подготовка DEV и контроля

1. Импортируйте фактическую группу организаторов через backend. Импорт сохраняет полный упорядоченный список версий. Для DEV нужны 60 чатов и 5 звонков, для контроля — 10 чатов. Идентификатор контрольной группы сообщают организаторы.
2. Зафиксируйте импортированные версии в приватном JSON. В примере замените `GROUP_ID` фактическим идентификатором группы. Первая команда сохраняет выборку. Вторая ставит её задания в очередь в рамках согласованного плана. Повтор с тем же путём восстанавливает прежние ID. Для контроля укажите `--dataset prod` и отдельный файл выбора.

```sh
python scripts/prepare_batch.py --dataset dev --group GROUP_ID --team DT20 --selection artifacts/private/dev-selection.json
python scripts/prepare_batch.py --dataset dev --group GROUP_ID --team DT20 --selection artifacts/private/dev-selection.json --enqueue
```

3. Официальное название команды — `DT20`, с точным регистром и без дополнительных пробелов. Поля `dataset` и `group_id` задают путь сдачи и фактическую импортированную группу. Объект `jobs` связывает каждый ID импортированной **версии** с одним ID задания по чек-листу `checklist-default-v1`. Для внешних вызовов нужны согласованные передача данных, бюджет и модель. Следующий фрагмент поясняет форму файла. Для настоящего экспорта требуется полный список.

```json
{"dataset":"prod","group_id":"<группа организаторов>","team_name":"DT20",
 "jobs":{"<ID импортированной версии>":"<ID поставленного задания>"}}
```

4. Дождитесь терминальных состояний. Проверьте, что CLI открывает ту же конфигурацию БД, с которой запущен backend. При повторном импорте с изменившимся составом или версиями старый выбор будет отклонён.
5. Выполните команды для соответствующего набора. Повторите для второго файла.

```sh
python scripts/submission.py export --selection artifacts/private/dev-selection.json
python scripts/submission.py validate --selection artifacts/private/dev-selection.json
python scripts/submission.py export --selection artifacts/private/prod-selection.json
python scripts/submission.py validate --selection artifacts/private/prod-selection.json
```

`export` читает импорт, выбранные задания, привязку к разрешённому плану, запросы, попытки и исторический чек-лист. Он проверяет версии, оригинальные ответы и сохранённый результат общими валидатором и scorer. Официальный снимок закреплён по ID и SHA-256 содержания `f172eb1ab664d3e4d11f1a55a6b34b51e6ca3fd7af0c402443f065b10b8c9437`. Смена рубрики сдачи потребует отдельного согласования с A.

В успешную запись попадают восемь исходных значений, пояснения и отсортированные позиции исходного транскрипта с 1. Пересечения диапазонов доказательств объединяются. Решения по апелляциям остаются в приложении. Сервер сохраняет коды ошибок, а экспорт формирует публичную причину из разрешённых сообщений. Модель и режим определяются фактическими вызовами, включая вызовы неуспешных заданий. Если во всём пакете ни одного вызова, CLI просит устранить проблему происхождения. Название модели из планов подставлять нельзя.

Программа сверяет кандидат JSON с ожидаемым документом и атомарно заменяет `results/dev/results.json` или `results/prod/results.json`. При ошибке прежний файл сохраняется. `validate` независимо читает существующий файл, заново собирает ожидаемые данные из БД и сравнивает имена полей, типы, значения и наборы ID. Дубли ключей, невалидный UTF-8, лишние поля и нечисловые итоги отклоняются. Код выхода 0 означает успешную локальную проверку.

Если задание ещё выполняется, обычный экспорт сразу возвращает ошибку. Дождитесь завершения выбранных заданий и повторите команду. Если к сроку останутся незавершённые задания или версии без задания (`null` в `jobs`), добавьте `--finalize-incomplete` при экспорте. Команда фиксирует в SQLite время, набор ещё выполняющихся заданий и их уже записанные вызовы. Эти диалоги войдут в файл как ошибки. Неуспешная проверка пакета откатывает фиксацию. Если во всей выборке нет ни одного записанного вызова, экспорт остановится.

Экспорт и проверка читают манифест группы, версии, оценки и вызовы модели из одного снимка SQLite. Если состав группы изменился до фиксации, устаревшая выборка отклоняется. Подготовка, экспорт и проверка сначала блокируют путь указанного selection JSON в `artifacts/private`. Они читают карту заданий под этой блокировкой. Экспорт и проверка затем блокируют набор `dev` или `prod` до окончания записи или проверки общего файла. При занятой блокировке команда сразу возвращает ошибку. Дождитесь завершения первого запуска и повторите команду с тем же selection JSON. Если подготовка добавила задания после предыдущего экспорта, повторите экспорт и затем проверку. Команда `validate` открывает публичный файл только для чтения.

Повторные экспорт и проверка той же выборки автоматически используют сохранённую границу, даже если задание с тех пор завершилось. Флаг `--finalize-incomplete` при проверке требует, чтобы граница уже была зафиксирована при экспорте. После финализации сохраните SQLite и исходный файл выбора до конца сдачи. Изменение состава группы, версии, выбранного задания или команды меняет выборку и требует отдельной проверки.

## Просмотр перед публикацией

Экспорт сводит переносы строк, табуляцию и повторяющиеся пробелы в `rationale` к одному пробелу. Затем проверяет полученное пояснение на секреты и копирование транскрипта. Исходное пояснение оценки остаётся в SQLite.

Выполните `python scripts/check_public_files.py` после точечного добавления двух результатов в индекс. Просмотрите staged diff, включая rationale, исходные ID, название команды и модель. Проверка ловит распространённые телефоны, почту, подписанные ссылки, токены и локальные пути. Имена и косвенные персональные сведения требуют отдельного просмотра. Для удаления лишних личных данных из публичного пояснения используйте процедуру ниже. Просмотр, commit, push и открытие обеих ссылок по SHA сдаваемой ветки должны завершиться до стоп-кода. Подробности формата и передачи организаторам есть в [спецификации сдачи](RESULTS_SUBMISSION.md).

### Проверенное скрытие персональных фрагментов

До финализации можно явно отметить фрагменты `explanation`, которые не должны попасть
в публичный `rationale`. Оценка модели в SQLite остаётся неизменной: сохраняются её
исходный текст, ответы, баллы и evidence. Экспорт заменяет только проверенные фрагменты
на фиксированный маркер `[данные скрыты]`. Нельзя передать новый текст пояснения,
значение критерия, балл или диапазон доказательства.

Подготовьте приватный JSON-массив записей в `artifacts/private/rationale-reviews.json`.
Каждая запись содержит:

- `evaluation_id` — ID уже успешного задания, выбранного в selection;
- `criterion_id` — внутренний ID `C01`–`C08`;
- `original_sha256` — SHA-256 **точного исходного** `explanation` в UTF-8, до нормализации пробелов;
- `reviewed_by` — кто действительно проверил фрагмент, например `Codex, review authorized by A`,
  если проверку выполнил агент по поручению A; не приписывайте её человеку;
- `reason` — `personal_data`, `secret` или `private_quote`;
- `spans` — непустой упорядоченный массив `{"start": 20, "end": 30}`. Индексы с нуля,
  правая граница не включается; это позиции Unicode-символов Python (`text[start:end]`),
  а не байтов UTF-8 или единиц UTF-16 браузера. Числа в примере иллюстративные.

Проверьте, что удаляется только частный фрагмент, а смысл обоснования сохраняется.
SHA-256, границы и проверяющий связывают правку с точным исходным ответом, но сами по себе
не доказывают сохранение смысла и не находят все персональные сведения автоматически.
Пересечения, дубли задания/критерия, другой исходный текст, чужое задание, пустой
результат и удаление всего пояснения отклоняются.

```sh
python scripts/submission.py review-rationales --selection artifacts/private/dev-selection.json --reviews artifacts/private/rationale-reviews.json
python scripts/submission.py export --selection artifacts/private/dev-selection.json
python scripts/submission.py validate --selection artifacts/private/dev-selection.json
```

Команда `review-rationales` работает офлайн и может применяться, пока остальные задания
пакета ещё выполняются. Она атомарно сохраняет **полный список** проверенных правок
в поле `rationale_redactions` selection под теми же блокировками, что экспорт.
Для удаления правок до финализации передайте пустой массив. Не редактируйте selection
параллельно вручную. Повтор `prepare_batch` сохраняет эти правки. После изменения
правок нужно заново выполнить экспорт и проверку.

`--finalize-incomplete` фиксирует также хеш списка правок. Менять его после финализации
нельзя, даже если все задания уже завершены; идентичный список можно применить повторно.
Изменение правок не создаёт новую границу и не превращает позднее завершившееся задание
в успешную строку. Старые границы совместимы с пустым списком правок. После экспорта
и перед commit всё равно просмотрите **весь** публичный JSON. Файлы reviews, selection
и исходные ответы остаются приватными и не входят в формат сдачи 1.0.

## История попыток при таймауте и перезапуске

Worker сохраняет отдельно резерв лимита, начало передачи HTTP-запроса и измеренный
результат попытки. Для локальной диагностики `app.storage.workflow.get_dispatches(id)`
возвращает номер попытки, провайдера, модель и время начала передачи. `get_calls(id)`
возвращает измеренные задержки и доступные сведения о токенах. Если worker успел
обработать отмену уже переданного HTTP-запроса, он сохраняет время от передачи
до прерывания. Неизвестные поля usage остаются пустыми. При аварийной
остановке после начала передачи могут отсутствовать ответ и измерения. Подтверждение
получения запроса сервером модели в таком случае неизвестно. Публикуемая строка
диалога получает `status="error"`, а известная модель берётся из сохранённого
события передачи. Один резерв лимита без передачи данных недостаточен для заголовка
`model`: команда экспорта отклонит пакет, в котором не было ни одной попытки отправки.
Ранее сохранённые результаты и снимки контрольного времени читаются в прежнем формате.

После записи подготовленной попытки worker повторно проверяет версию плана, состав
группы и срок запроса непосредственно перед передачей HTTP-транспорту. Время передачи
он фиксирует без повторного ожидания записи в SQLite, в отдельном коротком
файле рядом с базой, в каталоге `<имя файла SQLite>.handoffs/`. Подготовленная попытка
без отметки не попадает в экспорт. После измерения вызова его время сохраняется и
в самой SQLite. Переносите каталог вместе с остановленной базой, чтобы сохранить
сведения о вызовах, прерванных до измерения. Для исторических записей, созданных
прежней версией, сохраняется прежняя интерпретация журнала.
