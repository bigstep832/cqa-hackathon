# A-02: подготовка проверки качества DT20

**Обновление 8 ноября:** выполнен первый разрешённый Groq-прогон — 20 чатов,
остановка на первом звонке из-за HTTP 413. Метрики, ограничения разметки и остаток
задачи приведены в [A02_GROQ_DIAGNOSTIC](A02_GROQ_DIAGNOSTIC.md).
Ниже сохранён исторический отчёт офлайн-подготовки, а не текущий статус live.

Подготовлена офлайн-часть: памятка человеческой разметки, расширенный отчёт сравнения
и локальные входы DEV. Это не завершение A-02: независимые ручные эталоны,
разрешённый AI-прогон и измеренная точность пока отсутствуют.

Добавлен [локальный инструмент разметки в браузере](../evals/REVIEW_APP.md).
Он открывает эти же приватные входы, позволяет человеку выбрать примеры,
проверить состав частей, зафиксировать split и заполнить ответы без правки JSON.
Человеческая разметка настоящего DEV от этого автоматически не появляется.

## Что изменено

`evals/ANNOTATION_GUIDE.md` объясняет исходные C01–C08, отличия N/A от ошибки,
ступени C04/C06, направление флага C08, evidence, спорные случаи и независимость holdout.
Определения берутся из существующей рубрики; scorer, prompt и официальный snapshot
не изменялись. B продолжает интерфейс, C — workflow и экспорт.

`evals.compare` сохраняет прежние ключи метрик и добавляет таблицы ошибок,
precision/recall/F1 для N/A и boolean true, разбивку по языкам/каналам/рубрикам,
доли неуспеха и ожидания, полное совпадение диалогов, несовпадения null-итогов,
ссылки на расхождения и идентичность успешных оценок. Смешивание tune/holdout
или разных моделей/инструкций в одном сравнении отклоняется.

CLI читает только приватные входы; `--output` сохраняет новый приватный отчёт
без перезаписи. Ошибки валидации не выводят содержимое данных. Формат официальной
сдачи не меняется: диагностический отчёт не является `results.json` для жюри.

Группы и split намеренно не зафиксированы до человеческой проверки похожих сценариев.
Ручных ответов ноль. Эти приватные файлы не включены в Git и отсутствуют в клоне.
Для воспроизводимого сравнения C должен использовать эту БД либо явно сопоставить
те же immutable snapshots; новый импорт в другую БД создаст другие version IDs.

## Следующее действие A

1. Человек просматривает DEV, объединяет переводы/вариации и выбирает около 20–25
   диалогов с покрытием языков и каналов. Незаполненный scenario-review не является
   валидным файлом ScenarioAssignment: после проверки экспортируется обычный массив
   пар `conversation_version_id/scenario_group` для выбранных входов.
2. Подготовить пустой draft через `evals.prepare`, зафиксировать split до настройки,
   независимо заполнить ответы и проверить спорные случаи вторым человеком.
3. Выбрать провайдера/точную модель, право передачи и бюджет. Локальное скачивание
   DEV не разрешает передачу внешней модели. При согласовании сделать малый tune-прогон.
4. Проверить predictions относительно тех же snapshots, затем запустить сравнение:

```powershell
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m evals.compare --references data/private/references-tune.v1.json --predictions artifacts/private/predictions-tune.json --output artifacts/private/quality-tune.v1.json
```

Для holdout используется отдельный отчёт после фиксации pipeline. Стоимость всех
попыток и смысл evidence проверяются отдельно; compare не восстанавливает failed
usage и не устанавливает правильность человеческих ответов.

## Исправления аудита 8 ноября

Конфигурация `choice` теперь отклоняет пустые значения и строки с крайними пробелами
до сохранения чек-листа. Внутренние пробелы и RU/KZ/EN-значения сохраняются.
Для B/C: форма DTO, официальный чек-лист и scorer прежние; редактор должен передавать
непустые значения без крайних пробелов и показывать обычную ошибку валидации.
OpenAPI/TypeScript проверены штатными командами: производные файлы не изменились.

В ручной разметке все поля и кнопки блокируются на время сохранения и загрузки
сохранённого snapshot. Добавление/удаление evidence дополнительно защищено в
обработчиках; при ошибке сохранения введённые данные остаются в форме для исправления и повтора.

Проверено: 246 domain/evaluation-тестов, включая обёртку двух Node/JSDOM-регрессий,
Ruff, mypy (26 файлов), OpenAPI и TypeScript. Старый UI воспроизводимо проваливает

в их объёме не выявило. Это не исправление открытых замечаний B/C и не live-eval.
