# Защита и стоп-код

Владелец воспроизводимого demo и сдачи — C; A отвечает за смысл оценки,
B — за удобный и исправный UI. Общий лимит защиты — пять минут.

## Сценарий готового MVP

| Время | Действие | Что показать |
| --- | --- | --- |
| 0:00–1:00 | Открыть список и диалог | Язык, transcript, выбранные версии; запись звонка при наличии |
| 1:00–3:00 | Открыть исходную AI-оценку | Ответы/веса/баллы, evidence navigation, N/A с причиной, итог и C08 |
| 3:00–4:00 | Оспорить один критерий, принять решение | Причина, override/confirm, новый итог, сохранённый оригинал |
| 4:00–5:00 | Изменить критерий через UI и применить | Новая версия, фактический новый результат без правки кода |

Не представлять bootstrap mock как выполнение этого сценария.
Пока доступен только synthetic экран и переход к evidence; остальное — задачи MVP.
В live demo ошибка провайдера показывается как ошибка, без скрытой подмены mock.

## До 23-го часа

- C проверяет установку с чистого клона на другой машине команды по README.
- A фиксирует модель/инструкцию/pipeline/checklist и честный отчёт на отложенной части.
- B/C проходят обязательные браузерные сценарии, включая новый criterion и answer type.
- Команда репетирует ≤5 минут и готовит разрешённый офлайн JSON-резерв.
- C проверяет tracked/staged файлы, `python scripts/check_public_files.py`
  и вручную diff: никаких исходных PDF, URL с токенами, .env, DEV/control, аудио/SQLite/traces.
- C подтверждает публичную доступность cqa-hackathon, README и сдаваемого commit.
- Уполномоченный участник **заранее отправляет ссылку организаторам** предусмотренным способом.
  Само создание репозитория не означает, что ссылка отправлена.
  ИИ не отправляет внешнее сообщение без отдельного поручения.

## 23-й час: новые данные

Организаторы выдают новый group_id и 10 неизвестных транскриптов.
Загрузить через тот же pipeline, применить текущий checklist, дождаться результатов.
Не использовать заготовки по ID, ручные overrides как оригинальные AI-ответы
или непрерывную настройку на контроле. Сохранить provenance/usage/failures.

## 24-й час: фиксация

- Проверить `git status`, согласованный набор проверок и финальный commit.
- Выполнить `python scripts/freeze.py` в сдаваемом checkout.
- Проверить `artifacts/private/freeze.json`: git SHA и применённые версии.
- Подтвердить, что публичный commit совпадает со сдаваемой версией.
- После стоп-кода исходники не менять. Новые данные и checklist через UI
  допускаются на зафиксированной версии.

Точные дата/время стоп-кода ещё открыты; ориентир 24 часа от фактического старта.
Не запускать freeze-скрипт сейчас ради видимости сдачи.

## Что назвать честно

Для платной модели — название и приблизительная стоимость одной оценки,
включая retries/verify/repair. Неизвестная стоимость не равна нулю.
Для audio без mapping — переход к message и доступ к записи, без обещания точного seek.
При пропущенной проверке — причина, а не зелёная отметка. Синтетические примеры
явно обозначаются; реальные данные не выводятся в незащищённое публичное приложение.
