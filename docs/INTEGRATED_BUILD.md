## Установка в Windows

Нужны Git, Python 3.13 и Node.js 24. Команды выполняйте в PowerShell.
Для первого знакомства используйте новую папку, чтобы не затронуть рабочую БД команды:

```powershell
git clone --branch feat/release-integration-20261108 https://github.com/bigstep832/cqa-hackathon.git cqa-dt20
cd cqa-dt20
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
npm.cmd --prefix frontend ci
.\.venv\Scripts\python.exe scripts/export_contracts.py --check
npm.cmd --prefix frontend run generate:api:check
```

Если проект уже скачан, сначала сохраните свои изменения и проверьте `git status`.
Не делайте `reset --hard` и не заменяйте существующую SQLite. Можно скачать эту ветку
в отдельную папку приведённой выше командой.

Первый терминал, корень нового клона:

```powershell
$env:LIVE_EVAL_ENABLED = 'false'
$env:DATABASE_URL = 'sqlite:///./data/private/cqa.sqlite3'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Откройте второй терминал в том же корне:

```powershell
npm.cmd --prefix frontend run dev
```

Сайт: `http://127.0.0.1:5173`; API: `http://127.0.0.1:8000/docs`;
проверка сервера: `http://127.0.0.1:8000/health`.
Оба терминала должны оставаться открытыми. Если порт занят, не останавливайте чужой
процесс: закройте собственный прежний запуск или согласуйте свободные порты и прокси.
Настройки Origin в этом проекте рассчитаны на указанные адреса.

Для этого запуска ключ AI, `.env`, DEV и аудиофайлы не нужны. Live намеренно выключен.
Полноценная оценка реальных диалогов подключается отдельно по [GROQ](GROQ.md)
после согласования данных и лимитов; mock не применяется к DEV или контролю.

## Что показать команде

1. «Диалоги» → раскрыть ручной импорт → вставить встроенный учебный пример →
   отметить синтетическое происхождение → импортировать. Обновить страницу: запись сохранена.
2. В карточке открыть «Данные оператора», сохранить псевдоним; открыть «Операторы».
   Для расширенного примера импортировать `fixtures/synthetic/operator-profile.json`.
3. «Демо · mock» → «Оценить встроенный пример» → выбрать исходный чек-лист и Mock →
   «Запустить оценку». Показать состояние задания, итог 85,38, N/A и переход к доказательству.
4. Подать апелляцию C01 с комментарием → «Рассмотреть апелляции» → override → Нет →
   написать учебную причину → сохранить. Исходный балл 85,38 сохранён, эффективный — 70,00.
5. «Чек-листы» → исходная версия → «Редактировать — новая версия» → изменить вес или
   критерий → сохранить. Старая оценка остаётся связанной с v1.

Это репетиция интерфейса на синтетике. Она не доказывает качество реальной модели.
Демонстрация применения изменённого критерия реальной моделью требует отдельного
разрешённого прогона. Экран истории доступен в карточке импортированного диалога;
встроенный пример не заменяет проверку исторической оценки после переимпорта.

## Проверки и сборка

```powershell
.\.venv\Scripts\python.exe scripts/verify.py
$env:CQA_BROWSER_CHANNEL = 'msedge'
npm.cmd --prefix frontend run test:e2e
$env:CQA_TEST_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
npm.cmd --prefix frontend run test:e2e:history
```

Для штатных e2e нужен запущенный backend; Vite поднимается самим тестом.
История использует отдельные порты 8001/5174 и отдельную SQLite.
Точные результаты и границы проверки перечислены в [ACCEPTANCE](ACCEPTANCE.md).
`npm.cmd --prefix frontend run build` создаёт `frontend/dist`.
Этот каталог требует HTTP-сервера с маршрутизацией `/api` в backend;
открытие `index.html` через `file://` не заменяет запуск приложения.

Исходный код можно скачать ZIP-архивом ветки через GitHub. Приватные БД, транскрипты,
аудио, ключи и планы вызовов в него не входят. Доступ к настоящим данным настраивается
локально, а официальная сдача — отдельные два JSON по [RESULTS_SUBMISSION](RESULTS_SUBMISSION.md).
